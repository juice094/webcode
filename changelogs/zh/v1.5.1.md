# v1.5.1 (2026-10-26)

## 修复

- 多根工作区（Multi-root Workspace）下的路径解析：此前工具链只把工作区第一个
  文件夹当作沙箱根，导致 `../micro-server/pom.xml` 这类跨项目路径被
  「path must stay inside the VS Code workspace」误拒；写入
  `micro-server/src/...` 时会在第一个项目内部创建同名的假子目录；
  默认搜索也只覆盖第一个项目。现在文件读写、编辑、附件、命令目录的
  containment 校验对工作区全部文件夹取并集，路径首段写成兄弟文件夹名即可
  直达该项目，`..` 也能自然落到兄弟根。
- 默认 `search_files` / `search_code` 在多根工作区下逐文件夹扫描，
  结果带文件夹名前缀（如 `micro-server/src/App.java:12: ...`），
  `max_results` 预算全工作区共享。
- 浏览器桥接握手校验改为与加载器、网关 redemption 一致的最低版本语义：
  两端版本错位时不会再报晦涩的 "Invalid handshake parameters"，
  而是落到正常的版本不一致提示页（桥接协议版本仍要求精确一致）。

## 工程

- 新增 `workspacePath` 多根解析单元测试（兄弟根路由、假子目录防复发、
  `..` 越根、全根外拒绝、搜索目录解析、单根行为不变）。
- `workspaceRoots` 助手抽到 `extension/workspaceRoots.ts`，
  `gateway.ts` 保持在行数上限内。
