# v1.4.0 (2026-10-23)

## 行为变更（必读）

- **工具调用超时现在是真中止，不再是“放弃等待”**。截止时间到达时，网关会中止该次调用：
  `execute_command` 终止整棵进程树（POSIX 杀进程组，Windows 走 `taskkill /T /F`），`search_code`
  与 `search_files` 终止 ripgrep 进程，`read_file` 关闭文件句柄。旧版本超时后命令仍在后台继续运行。
  超时文案从 `is not a cancellation` 改为 `aborted the call`，依赖该文案的调用方需要同步调整。
- **客户端断开连接会中止正在执行的工具调用**。旧版本会继续执行到结束再丢弃结果。

## 新增

- 工具调用并发门：同时执行的调用上限为 4，超出部分按先进先出排队。客户端在排队期间断开会释放队列位置。
- 停止网关时先中止在途调用再清理注册表，仍在清理的调用能跑完自身的收尾逻辑。

## 性能

- `read_file` 的 `tail` 读取改用环形缓冲：此前每读一行都要搬移整个窗口数组，大文件下是
  O(行数 × tail) 的同步开销，会阻塞扩展宿主的事件循环。
- `search_code` 与 `search_files` 的 ripgrep 输出改用游标消费，消除了逐行重建大字符串的二次复杂度。
- 工具定义与 schema 按上下文缓存，避免每次调用都重建描述字符串与浅拷贝 schema。

## 修复

- 在途调用注册表改由 `finally` 统一结束，成功、超时、失败、断连四条路径收敛到一处，不再泄漏条目。
- 同一毫秒内的两次调用曾共用 `call-<timestamp>` 作为调用 ID，现改为 UUID。
- 测试改用 `port: 0` 让系统动态分配端口，避免 Windows 保留端口段（Hyper-V/WSL2/Docker）导致的
  `EADDRINUSE` 误报。`webcodeGateway.port` 配置为 `0` 时网关会绑定系统分配的任意端口。

## 内部

- 本地工具与 MCP 工具共用同一条执行与遥测路径，新增执行后端不再需要复制超时、追踪与错误映射逻辑。
- 新增 `processTree`、`toolConcurrency`、`abortUtils`、`readFileLineSelection` 四个模块，
  分别承担跨平台进程终止、并发门、中止文案与行选择解析。
