# v1.9.0 (2026-11-24)

## 改进

- 能力快照内联，消除初始化轮次：新增内部工具 `get_capability_snapshot`，
  渲染紧凑能力快照（工具调用签名由 inputSchema 生成，含 read-only /
  destructive 标注，以及带 `skillFilePath` 的技能清单），由桥侧组装进
  初始化内容。模型按任务意图直接调用工具，不再需要在任务前跑
  `list_tools` / `list_skills` 清点轮；两者保持模型可调用，降级为按需
  刷新（需要完整 inputSchema 或能力变动后）。
- 初始化头部文案按快照是否存在分流：旧网关无快照工具时自动回退到
  `list_tools` 引导文案，新旧混配不中断。
- 契约提示词（中英）转向 intent-first：快照即事实来源；新增「接管模式」
  一节——会话已有历史或工作区已有未完成改动时，用最小代价恢复现场，
  状态恢复与第一个真实动作放在同一轮；行为准则新增「元操作静默」；
  写类调用缺结果时读回确认未执行才重试、同一目标上限一次；多调用反例
  改用 text 代码块，防止被网关误捕获。
- 结果形态章节对齐实现：工具结果早已是纯文本句文格式（避免 JSON 转义
  在每一轮重复计费），但提示词仍教模型期待 `mcp_action: "result"` JSON
  包装。本次改写为真实形态——单行内联 / 自适应围栏 / 无输出 / 失败，
  并说明批次末尾的周期性协议提醒与超限 txt 附件。
- 协议错误反馈不再邀请重复初始化：`initialize` 调用格式仅在会话尚未
  完成初始化时附带（新增会话级标志），此后的格式错误只回标准调用格式。
- 删除死资源 `error_hint_zh/en`：只播种加载、无运行时消费；活的协议
  错误反馈由 `buildProtocolErrorMessage` 按解析问题动态生成。
- bridge 与 gateway 版本升至 1.9.0；初始化契约文本（网关下发）引用桥侧
  组装的快照，新旧必须配套，故 `minExtensionVersion` 同步升至 1.9.0，
  旧桥接入会收到 409 版本不匹配提示并引导升级。
