# v1.7.4 (2026-11-04)

## Improved

- Writes may now batch: the control-flow contract clarifies that serial
  execution is an execution semantic, not a batching constraint — the
  gateway already executes mutating calls one by one in JSON block order
  (write lock FIFO). Batched writes run serially in block order, results
  arrive in the same order, and one failed write does not stop the rest.
  Only true data dependencies (arguments needing an earlier result, or
  read-after-write on the same file) must split across rounds. This aligns
  with the dsh-side D1 semantics and cuts multi-file tasks from N rounds
  to 1.
