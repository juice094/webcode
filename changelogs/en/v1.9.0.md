# v1.9.0 (2026-11-24)

## Improved

- Capability snapshot embedded in the initialization payload, eliminating
  the pre-task inventory round: the new internal tool
  `get_capability_snapshot` renders a compact snapshot (tool call signatures
  generated from each inputSchema with read-only/destructive hints, plus the
  skill list with `skillFilePath` entries), which the bridge assembles into
  the initialization content. The model calls tools directly as the task
  requires instead of running `list_tools` / `list_skills` warm-up rounds;
  both remain model-callable as on-demand refresh (for a full inputSchema or
  after capabilities change).
- The initialization header adapts to snapshot availability: against an
  older gateway without the snapshot tool it falls back to the `list_tools`
  guidance, so mixed old/new pairings keep working.
- The contract prompts (zh/en) move intent-first: the snapshot is the source
  of truth; a new "Takeover Mode" section covers sessions with history or
  unfinished workspace changes — recover state at minimal cost and fold it
  into the first real action; behavior guidelines add "silent
  meta-operations"; missing write results require a read-back confirmation
  before a single retry; the multi-call counterexample now uses a text code
  block so the gateway cannot mis-capture it.
- The result-shape section now matches the implementation: tool results have
  long been plain-text outcomes (avoiding JSON escaping costs on every
  round), but the prompts still taught an `mcp_action: "result"` JSON
  wrapper. Rewritten to the real shapes — inline single-line / adaptive
  fence / no output / failure — plus the periodic batch reminder and the
  oversize txt attachment.
- Protocol error feedback no longer invites a redundant re-init: the
  `initialize` call format is attached only before the first successful
  initialization (a new session-scoped flag); later format errors return the
  standard call format only.
- Removed the dead `error_hint_zh/en` resources: they were seeded and loaded
  but never consumed; live protocol error feedback is built dynamically from
  parse issues by `buildProtocolErrorMessage`.
- Bridge and gateway versions raised to 1.9.0. Because the contract text
  served by the gateway references the snapshot assembled on the bridge side,
  `minExtensionVersion` moves to 1.9.0 as well; older bridges get a 409
  version-mismatch hint pointing at the upgrade.
