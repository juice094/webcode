# v1.4.0 (2026-10-23)

## Behavior changes (read this)

- **A tool call timeout now aborts the call instead of abandoning the wait.** When the deadline
  fires, the gateway aborts the call: `execute_command` terminates the whole process tree (process
  group on POSIX, `taskkill /T /F` on Windows), `search_code` and `search_files` kill their ripgrep
  process, and `read_file` closes its file handle. Previously the command kept running in the
  background after the timeout. The timeout text changed from `is not a cancellation` to
  `aborted the call`; callers that match on that wording must be updated.
- **A client disconnect aborts the running tool call.** Previously the work ran to completion and
  the result was discarded.

## Added

- Tool call concurrency gate: at most 4 calls execute at once, and the rest queue in FIFO order. A
  client that disconnects while queued gives up its place.
- Stopping the gateway aborts in-flight calls before clearing the registry, so calls still cleaning
  up can finish their own teardown.

## Performance

- `read_file` tail reads use a ring buffer. The previous implementation shifted the whole window
  array per line, which was O(lines x tail) synchronous work that blocked the extension host event
  loop on large files.
- `search_code` and `search_files` consume ripgrep output with a cursor, removing the quadratic
  string rebuild per line.
- Tool definitions and schemas are cached per context, so a call no longer rebuilds description
  strings and shallow-copies the schema every time.
- Compiled glob patterns are cached: a workspace walk used to rebuild the regex once per file,
  which is 100k compilations for a 100k-file workspace.
- The in-process fallback search (used when ripgrep is unavailable) scans with bounded concurrency
  (8 workers) and stops at `max_results`, while still returning results ordered by path.

## Fixed

- The in-flight call registry is finalized from a single `finally`, so success, timeout, failure,
  and disconnect all converge and the registry cannot leak an entry.
- The rate limiter compacts its window in place instead of allocating a new array per request, and
  sweeps expired keys so a client rotating its origin cannot grow the map forever.
- Approval challenges and grants expire lazily on access and are swept periodically, instead of
  scanning both maps on every operation.
- Two calls in the same millisecond shared `call-<timestamp>` as their call id; it is now a UUID.
- Tests use `port: 0` so the OS assigns the port, avoiding false `EADDRINUSE` failures from Windows
  reserved port ranges (Hyper-V/WSL2/Docker). Setting `webcodeGateway.port` to `0` binds an
  OS-assigned port.

## Internal

- Local and MCP tools share one execution and telemetry path, so a new backend no longer copies the
  deadline, trace, and error-mapping sequence.
- New modules `processTree`, `toolConcurrency`, `abortUtils`, and `readFileLineSelection` own
  cross-platform process termination, the concurrency gate, abort wording, and line-selection
  parsing respectively.
- A third-party MCP tool can declare a path argument with `format: "workspace-relative-path"` in its
  schema; the gateway then enforces the workspace boundary automatically. Adding a path-taking MCP
  tool no longer requires editing a hard-coded gateway allowlist, which is kept as a fallback.
