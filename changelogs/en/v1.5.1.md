# v1.5.1 (2026-10-26)

## Fixed

- Path resolution in multi-root workspaces: the toolchain previously treated
  only the first workspace folder as the sandbox root, so cross-project paths
  like `../micro-server/pom.xml` were rejected with "path must stay inside
  the VS Code workspace"; writing `micro-server/src/...` created a fake
  same-named subdirectory inside the first project; and default searches only
  covered the first project. Containment checks for file read/write/edit,
  attachments, and command directories now accept the union of every
  workspace folder, a path prefixed with a sibling folder name addresses that
  project directly, and `..` resolves naturally into a sibling root.
- Default `search_files` / `search_code` sweep every workspace folder in a
  multi-root workspace, prefixing results with the folder name (e.g.
  `micro-server/src/App.java:12: ...`). The `max_results` budget is shared
  across the whole workspace.
- The browser bridge handshake check now uses the same minimum-version
  semantics as the loader and gateway redemption: a version skew no longer
  fails with the cryptic "Invalid handshake parameters" and instead reaches
  the proper version-mismatch page (the bridge protocol version itself must
  still match exactly).

## Engineering

- Add multi-root `workspacePath` unit tests (sibling routing, fake-subdirectory
  regression, `..` across roots, rejection outside every root, search
  directory resolution, unchanged single-root behavior).
- Extract `workspaceRoots` helpers into `extension/workspaceRoots.ts` to keep
