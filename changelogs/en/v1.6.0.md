# v1.6.0 (2026-11-02)

## Added

- Multiple browser sessions per workspace: each bridge redemption issues its
  own session token tracked in a session registry; tokens persist per
  workspace in workspaceState (legacy SecretStorage single token migrates on
  first start), so connected tabs survive restarts.
- `sessionIdleTimeoutMinutes` setting (default 30, `0` disables): sweeps
  idle sessions and force-releases their write locks; adds a
  `disconnectBrowsers` command; session count shown in the status bar and
  `/v1/ping` (older bridges keep working via `sessionActive`).
- Cross-browser write lock: mutating tool calls (`execute_command`,
  `run_in_terminal`, `edit_file`, `write_file`, `terminal_session`) are
  serialized behind a per-gateway write lock with FIFO queueing,
  cancellation, and a 30s retryable timeout; audit events never log tokens
  or arguments.
- The bridge popup can connect while the gateway already has sessions,
  labeling the button with the live session count from `/v1/ping`; gateways
  without sessionCount fall back to the previous busy state.
- Redemption failures now hint at version mismatch on 409 and forbidden
  origin on 403, with zh/en messages.
- Bridge and gateway versions raised to 1.6.0 with `minExtensionVersion`
  1.6.0.

## Improved

- Discovered-gateway protocol gains an optional `sessionCount` field;
  malformed counts degrade to unknown instead of failing.
