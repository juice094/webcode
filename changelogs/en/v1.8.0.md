# v1.8.0 (2026-11-16)

## Improved

- Slimmer initialization payload: the initialization content now carries only
  the control flow contract, project rules, and project context. The
  `# Available Tools` / `# Available Skills` JSON blocks are no longer
  embedded, which substantially shortens the text written back into the chat
  box and fits newer models with stricter long-text reading limits.
- Lazy tool/skill lists: `list_tools` and `list_skills` are now callable by
  the model directly in the conversation (still approval-free). The
  initialization header and the contract prompts now instruct the model to
  call `list_tools` before starting a task (and `list_skills` when skills are
  needed); their results are the single source of truth for available tools
  and skills. `get_project_rules` and `get_project_context` remain reserved
  for initialization assembly, and the rejection message for direct model
  calls no longer names the product.
- Bridge and gateway versions raised to 1.8.0. Because the initialization
  payload is assembled on the bridge side and the contract text must match,
  `minExtensionVersion` moves to 1.8.0 as well; older bridges get a 409
  version-mismatch hint pointing at the upgrade.
