# v1.5.2 (2026-10-31)

## Added

- `command.requireApproval` switch (default `true`): when set to `false`,
  `execute_command` / `run_in_terminal` assessments that would require
  confirmation are downgraded to allowed; `blocked` results and
  `command.denyRules` still apply unchanged.
- `command.allowRules` whitelist: substring rules using the same matching as
  denyRules; matching commands are exempt from the approval prompt only and
  never bypass the blocking layer. Suited for agent workflows built on
  `$(...)`, `node -e` and heredocs that previously hit a prompt per command.
- New prompt rules: write operations (edit_file/write_file) must run serially
  while read-only calls may batch; commands estimated over 10 seconds
  (builds, tests, installs) must be sent individually; never conclude from
  truncated tool results; read the target before destructive edits and
  prefer dryRun diffs.

## Improved

- Prompt clarification: when showing example tool-call formats to the user,
  use a plain code block or mark them as examples so pure illustrations are
  not mistaken for real calls.
- A one-line progress statement alongside tool calls is allowed, but
  questions remain forbidden in the same reply.
- Rule 7 now states that mentioning absolute paths in prose or `purpose` is
  fine, but the `path` argument passed to tools must stay workspace-relative.
