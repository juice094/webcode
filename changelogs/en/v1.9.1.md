# v1.9.1 (2026-11-24)

## Fixed

- Capability snapshot signatures now support `oneOf` schemas: tools with
  `oneOf` input schemas such as `edit_file` and `terminal_session` were
  rendered with empty parentheses `()`, leaving the model unable to tell
  their required arguments — the core write tool was effectively unusable.
  Signatures now render as "required in every branch + branch-exclusive
  alternatives (e.g. `edits | patch`) + union of optionals", and `enum`
  parameters carry their values (e.g. `action: list|read|stop|close`).
- The snapshot note and the contract prompts now declare `list_tools` /
  `list_skills` as always-available meta tools that are intentionally not
  listed among the business tools, resolving the conflict with "do not
  assume tools outside the snapshot"; refreshed results override the inline
  snapshot.
- The contract prompts close the `run_in_terminal` loop: the call returns a
  `session_id` immediately (a handle, not the result); read the captured
  output on the next round with `terminal_session` (`action: "read"`).
- The "use text blocks for examples" rule is scoped to explaining the format
  to the user; the json code blocks inside the document are real call-format
  templates.
- The long-running command rule changed from model estimation to explicit
  declaration: send such commands as their own batch with a `timeout`
  declaring the expected duration (default 60s, ceiling 1800s).
- Documented environment facts: `search_files` / `search_code` follow
  `.gitignore`-style ignore files and silently skip ignored directories —
  use `execute_command` instead; `execute_command` defaults to a Git Bash
  (POSIX) profile, pass `profile` for other shells; before overwriting an
  existing file with `write_file`, read_file to confirm the content has not
  changed under you — new files need no pre-check.
